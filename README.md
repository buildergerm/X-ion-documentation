# X-ion Draft & Scrutium Documentation

This docs covers full ducumentation of X-ion Organization products documentation.

Official product documentation for **Scrutium AI** — chat, research, and build with privacy by default. Built by **X-ion Team**.

## What this site covers

- Getting started and accounts
- Chat, models, tools, and thinking UI
- Projects and Build mode
- Library and Memory
- Account settings, privacy, and safety
- Developer setup and database migrations

## Stack

- Next.js 15 App Router
- MDX + Contentlayer2
- Tailwind CSS 4
- Static export for Cloudflare Pages

## Local development

Requirements: Node.js 20.9+ and pnpm.

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Documentation content lives in `/docs` as MDX. Navigation is configured in `config/sidebar.tsx`.

To verify the production build locally:

```bash
pnpm build
```

The static site is generated in `out/`.

## Deploy to Cloudflare Pages

This repository is configured for **Cloudflare Pages static hosting**. No server runtime or application secrets are required for the documentation site.

1. Push the repository to GitHub.
2. In the Cloudflare dashboard, open **Workers & Pages → Create → Pages → Connect to Git** and select `buildergerm/scrutium-documentation`.
3. Set the production branch to `main`.
4. Use these build settings:

   | Setting | Value |
   | --- | --- |
   | Framework preset | Next.js (Static HTML Export) |
   | Build command | `pnpm build` |
   | Build output directory | `out` |
   | Root directory | `/` |
   | Node.js version | `20.19.0` |

5. If using a custom domain, add the Pages domain in **Custom domains** and set the `NEXT_PUBLIC_SITE_URL` build environment variable to the canonical HTTPS URL (for example, your actual docs domain). The metadata configuration uses this value for canonical and social metadata.
6. Save and deploy. Cloudflare will build and redeploy when commits land on `main`.

The repository includes a `public/_redirects` file for the documentation landing redirects. Next.js middleware is intentionally not used because static export does not support middleware.

### Build settings and limitations

- Build output: `out/` (generated by `next build`).
- The docs routes are generated at build time from MDX files.
- Images are configured as unoptimized so they work without a Next.js image server.
- This is a static documentation site. Server actions, API routes, middleware, and other request-time Next.js features are not available in this deployment. If you add them later, revisit the hosting architecture.

For current platform instructions, see the [Cloudflare Pages static Next.js guide](https://developers.cloudflare.com/pages/framework-guides/nextjs/deploy-a-static-nextjs-site/) and [build configuration reference](https://developers.cloudflare.com/pages/configuration/build-configuration/).
